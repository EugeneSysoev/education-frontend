# Accordion exercise

## Цель

Отработать локальное состояние, props, обработчики событий, условный рендеринг и подъём состояния. Redux и `useEffect` здесь не нужны.

## Stage A — независимые панели

1. Создайте отдельный компонент для одной панели.
2. Отобразите все элементы из `items`; используйте `id` как `key`.
3. Каждая панель самостоятельно хранит `isOpen` через `useState(false)`.
4. Кнопка открывает и закрывает только свою панель.
5. Одновременно может быть открыто любое количество панелей.
6. Текст кнопки или визуальный индикатор должен показывать текущее состояние.

## Stage B — только одна открытая панель

После review Stage A:

1. Поднимите состояние в `Accordion`.
2. Храните минимальное состояние: ID открытой панели либо отсутствие ID.
3. Сделайте компонент панели управляемым через props `isOpen` и `onToggle`.
4. Открытие панели закрывает ранее открытую.
5. Повторное нажатие на открытую панель закрывает её.

## Требования TypeScript

- Не использовать `any` и type assertions `as`.
- Описать props каждого компонента.
- `items` остаётся readonly; не мутировать входной массив.

## Доступность

- Переключатель — настоящий `<button type="button">`.
- Кнопка содержит `aria-expanded`.
- Кнопка через `aria-controls` связана с уникальным `id` панели.
- Заголовок остаётся видимым независимо от состояния.

## Перед кодом

Ответьте комментариями в `Accordion.tsx`:

1. Где будет жить состояние в Stage A?
2. Какой компонент отвечает за изменение этого состояния?
3. Какие props нужны компоненту одной панели?
4. Почему для Stage A не требуется `useEffect`?
