# Контекст для Codex

Этот репозиторий — единая учебная система подготовки к Frontend-разработке. Перед любой учебной работой откройте [хронологию](docs/learning/README.md), затем прочитайте файл активного дня и связанные с ним исходники. При начале занятия, составлении плана и переносе задач используйте [систему обучения и график](docs/learning/learning-system.md).

Локальная папка: `C:\Users\User\Desktop\education-frontend`. Официальный GitHub-репозиторий: [EugeneSysoev/education-frontend](https://github.com/EugeneSysoev/education-frontend). Используйте его как `origin` для обязательного push при завершении дня.

В Codex служебная папка `.git` этого checkout может быть доступна только для чтения. В таком случае сверяйтесь с `origin/main` через свежий clone, создавайте обычный последующий commit от актуального remote HEAD и никогда не используйте force push.

## Учебный контракт

- Если ученик не знает, как решать задачу, сначала кратко объясните теорию простыми словами, затем ведите практику по одному небольшому шагу. Ученик выполняет попытку, Codex проверяет результат и даёт минимальную необходимую помощь; формат описан в системе обучения.
- Проверяйте корректность, TypeScript, читаемость, архитектуру и способность ученика объяснить поток данных и компромиссы.
- Объяснения и журналы ведите на русском. Имена файлов, компонентов, переменных, типов и сообщения коммитов пишите на английском.
- Занятия идут по согласованному графику. При нехватке времени уменьшайте объём задачи и явно переносите остаток. Базовая тема освоена, когда ученик решает типовую задачу, объясняет решение и воспроизводит ключевую часть без копирования.
- При планировании следуйте интенсивному распорядку и действиям по четырём книгам из системы обучения; первый цикл задан в [плане 2–8 октября](docs/learning/2026-10-02-week-plan.md). Ведите одну главную задачу, фиксируйте время и результат каждого блока, переходите к коду после минимального review плана. Исторические журналы сохраняют фактическое время прежних занятий.

## Обязательное завершение учебного дня

День можно пометить завершённым только когда выполнены все пункты:

1. В файле дня заполнены фактический результат, затраченное время, ошибки, полученная помощь и тема для повторения.
2. Обновлены `docs/learning/README.md` и `learning-log/skills-matrix.md` на основании наблюдаемого результата.
3. Запущены относящиеся к работе тесты, TypeScript-сборка и линтер; результат записан в файл дня.
4. Все изменения собраны в осмысленный Git-коммит и отправлены в настроенный remote.
5. Создан и связан из хронологии план следующего учебного дня с первым конкретным шагом.

Если commit или push невозможен, зафиксируйте точную причину в файле дня и не отмечайте день завершённым.
