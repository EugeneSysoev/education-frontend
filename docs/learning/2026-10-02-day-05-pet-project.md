# День 5 — старт пет-проекта с ментором

Дата: 2 октября 2026
Статус: запланирован; ожидаются требования проекта от ученика
Начало: 08:00, Asia/Bangkok, подтверждено учеником 1 октября.
Окончание: 16:15. План: 7 часов активной работы и 75 минут перерывов по [интенсивному распорядку](learning-system.md).

## Цель дня

Зафиксировать требования ментора, выбрать минимальный пользовательский сценарий и начать его реализацию по [учебному графику](learning-system.md). В прежнем журнале проект называется «Кинопоиск»; подтвердить это по новой информации ученика.

## Первый конкретный шаг

Прочитать присланное учеником задание. Записать обязательные функции, стек, API, макет, репозиторий и срок ментора. Выбрать один небольшой сценарий и сформулировать: «Пользователь делает … и получает …». Разделить его на шаги по 5–15 минут; начать с первого шага после короткого объяснения нужной темы.

## План в пределах занятия

1. Зафиксировать один результат дня и критерий готовности.
2. В утренних блоках 08:15–11:30 продвинуть выбранный сценарий; подготовку окружения учитывать в этих блоках. В 13:15–14:45 интегрировать результат и проверить граничные случаи.
3. В блоке пробелов разобрать одну тему, реально мешающую сценарию, и применить её в проекте.
4. Проверить результат, объяснить поток данных и заполнить фактический журнал.
5. Оформить результат для GitHub и следующий шаг.

Если требования ещё не поступили, статус остаётся «ожидаются требования». Hacker News
реализован и проверен в [занятии 1–2 октября](2026-10-01-hacker-news.md); для закрепления
можно без копирования объяснить unknown и Promise.all на новом коротком примере.
Это повторение не записывается как начало неизвестного проекта.

## Распределение завтрашних блоков

Часы, длительности и перерывы заданы только в системе обучения; здесь зафиксировано содержание блоков:

| Блок | Содержание | Критерий результата |
|---|---|---|
| Старт | Прочитать требования ментора и вчерашний журнал; выбрать результат | Ученик сформулировал один сценарий и первый шаг |
| Проект 1 | Уточнить обязательный MVP, проверить окружение, начать минимальную реализацию | Окружение запускается, первый участок доступен для проверки |
| Проект 2 | Продолжить тот же сценарий | Данные или действие пользователя проходят первый рабочий участок |
| Пробел | Одна мешающая тема: API/Promise, state/effects, TypeScript или преобразование данных по факту | Маленькое упражнение выполнено и решение перенесено в проект |
| Проект 3 | Соединить части сценария и проверить основной путь | Рабочий путь либо конкретный остаток задачи |
| Review | Проверки по изменённому коду, объяснение, факт по блокам | Записаны результаты и степень помощи |
| Подготовка к работе | Оформить изменения, подготовить описание результата и первый шаг завтра | Результат сохранён, продолжение понятно |

Клир: начать с маленького действия и отметить результат. Келлер: один сценарий занимает главные блоки. Ким и Моборн: сократить лишние действия, повысить полезность практики. Чалдини: ученик сам записывает обещание дня и сверяет его с фактом. Подробности и источники — в системе обучения.

- Требования ментора записаны, обязательный MVP отделён от дальнейших идей.
- Выбран один сценарий, указаны ближайшие шаги и критерии проверки.
- Фактический результат и остаток работы названы прямо.
- Пробел связан с конкретным шагом проекта; помощь зафиксирована.
