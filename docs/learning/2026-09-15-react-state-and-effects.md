## Accordion: локальное состояние

В Stage A каждая панель самостоятельно хранила состояние:

```tsx
const [isOpen, setIsOpen] = useState(false);
```

Каждый экземпляр `Panel` получает собственное состояние. Поэтому открытие одной панели не влияет на остальные.

Обработчик события нужно передавать как функцию:

```tsx
onClick={handleClick}
```

Вызов setter во время рендера недопустим:

```tsx
const handleClick = setIsOpen(true);
```

Такая запись меняет состояние прямо при выполнении компонента и может вызвать бесконечные повторные рендеры. Правильный обработчик выполняет изменение только после клика.

## Функциональное обновление состояния

Когда новое значение зависит от предыдущего, используется callback:

```tsx
setIsOpen((previousIsOpen) => !previousIsOpen);
```

Название `previousIsOpen` выбирает разработчик, а актуальное значение передаёт React.

Если новое значение известно заранее, callback не нужен:

```tsx
setIsRunning(true);
setIsRunning(false);
setSeconds(0);
```

Поэтому Start и Pause задают конкретные значения, а не переключают `isRunning` через отрицание.

## Списки, `map`, `key` и `id`

`items.map(...)` вызывает callback для каждого элемента массива. Параметр `item` содержит текущий объект, поэтому используются `item.id`, `item.title` и `item.content`.

```tsx
items.map((item) => (
  <Panel key={item.id} id={item.id} />
));
```

- `key` нужен React для сопоставления элементов списка между рендерами.
- `key` не передаётся компоненту как обычный prop.
- `id` передаётся отдельно и может использоваться в DOM.
- Стабильный `id` нельзя заменять новым `crypto.randomUUID()` при каждом рендере.

Для доступности кнопка сообщает состояние панели и связывается с её содержимым:

```tsx
aria-expanded={isOpen}
aria-controls={contentId}
```

Это стандартные ARIA-атрибуты HTML, а React передаёт их DOM-элементу.

## Подъём состояния и управляемый компонент

В Stage B правило «открыта только одна панель» потребовало общего состояния в `Accordion`:

```tsx
const [openPanelId, setOpenPanelId] = useState<string | null>(null);
```

- строка хранит `id` открытой панели;
- `null` означает, что все панели закрыты;
- `isOpen` конкретной панели вычисляется сравнением `openPanelId === item.id`;
- `Panel` больше не хранит `useState`, а получает `isOpen` и `onToggle` через props.

Переключение основано на двух значениях:

```text
currentOpenPanelId — какая панель открыта сейчас
panelId            — по какой панели кликнули
```

Если значения совпали, состояние становится `null`. Иначе открытой становится панель с нажатым `id`.

## Timer и `useEffect`

Timer хранит минимальное состояние:

```text
seconds: number
isRunning: boolean
```

Клик по кнопке не вызывает эффект напрямую. Последовательность выглядит так:

```text
событие → изменение состояния → рендер → effect или cleanup
```

Интервал — браузерный механизм, который повторно вызывает callback через заданное время:

```tsx
const intervalId = setInterval(callback, 1000);
clearInterval(intervalId);
```

`1000` миллисекунд соответствует одной секунде. Возвращаемый `intervalId` позволяет остановить именно созданный интервал.

Массив зависимостей:

```tsx
[isRunning]
```

сообщает React, что эффект нужно повторить при изменении `isRunning`. Изменение `seconds` само по себе не перезапускает эффект.

Cleanup выполняется перед повторным запуском эффекта и при размонтировании компонента. Это предотвращает одновременную работу нескольких интервалов.

Секунды обновляются функционально:

```tsx
setSeconds((previousSeconds) => previousSeconds + 1);
```

Так callback интервала получает актуальное предыдущее значение от React и не зависит от устаревшего значения `seconds` из старого рендера.

## Ошибки, которые важно узнавать

1. Setter вызывается во время рендера вместо передачи обработчика.
2. В JSX условие написано как текст без фигурных скобок.
3. Внутри `map` используются несуществующие `id`, `title`, `content` вместо свойств `item`.
4. Для стабильных данных генерируется новый `id` при каждом рендере.
5. Команды Start, Pause и Reset ошибочно реализуются как одинаковый toggle.
6. Интервал создаётся без `clearInterval`.
7. `seconds` добавляется в зависимости эффекта, из-за чего интервал пересоздаётся на каждом тике.
