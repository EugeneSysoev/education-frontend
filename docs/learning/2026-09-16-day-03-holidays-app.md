## Контекст

Ментор назначил задачу [«Приложение для праздников»](https://teal-produce-2f9.notion.site/25e1f21638f58191a2c0e104fcaf48cd). На выполнение и закрепление задач React Practice Calendar отведена неделя. Пробелы JavaScript и TypeScript закрываются внутри React-практики на реальных местах: Promise, `fetch`, массивы, обработка ошибок, `unknown`, type guards и типизация API.

## Цель дня

Спроектировать поток данных и довести до первой рабочей версии приложение, которое показывает государственные праздники текущего года для выбранной страны. Нидерланды выбраны по умолчанию.

Условие и критерии: [`react-lab/src/exercises/holidays-app/README.md`](../../react-lab/src/exercises/holidays-app/README.md).

## Закреплено

- `key` определяет идентичность элемента среди соседей и не передаётся как обычный prop.
- Функциональный setter нужен, когда следующее состояние зависит от предыдущего.
- Cleanup эффекта очищает внешний ресурс перед повторным запуском эффекта и при размонтировании компонента.

## Блок 3 — TanStack Query, 75 минут

1. Подключить `QueryClientProvider`.
2. Получить список стран отдельным query.

Критерий: данные сервера находятся в TanStack Query, а выбранная страна — в локальном React state.

## Блок 4 — интерфейс и состояния, 60 минут

Критерий: смена страны обновляет список без перезагрузки страницы; каждый результат интерфейса соответствует одному явному состоянию запроса.

## Журнал дня

- Фактическое время: в ходе сессий не фиксировалось; задним числом не восстановлено.
- Результат: собрана первая рабочая версия Holidays App. Приложение загружает страны, выбирает `NL` по умолчанию, получает праздники выбранной страны за текущий год и показывает loading/error/empty/success состояния.
- Что получилось самостоятельно: изучить фактический ответ API в DevTools, исправить минимальные TypeScript-типы, выполнить последовательные правки запросов и JSX, проверить смену стран и скорость повторного выбора за счёт кэша.
- Где потребовалась помощь: построение data layer, назначение `queryKey`/`queryFn`, форма объекта, возвращаемого `useQuery`, controlled `<select>`, условный рендер состояний запроса и логика пустого результата.
- Ошибки и их причины: сначала смешивались поля объекта и массива; результат query принимался за Promise с данными; пустое состояние не исключало одновременный рендер пустого списка. Причина — недостаточно ясное разделение ответа API, query observer и состояния интерфейса.
- Что могу объяснить своими словами: `queryKey` идентифицирует запись кэша; `queryFn` получает данные; страна и год входят в ключ праздников, потому что определяют набор данных; выбранная страна является local state, а страны и праздники — server state.
- Что повторить: типизация недоверенного JSON через `unknown` и type guards; отличие сетевой ошибки от HTTP-ответа с ошибочным статусом; воспроизведение запроса и четырёх UI-состояний без копирования.
- Замечания ментора: Holidays App назначен основной практикой по fetching data.
- Энергия от 1 до 5: не фиксировалась.
