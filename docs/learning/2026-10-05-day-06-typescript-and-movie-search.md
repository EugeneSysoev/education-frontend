## Первый шаг — 10–15 минут

Без копирования Kanban написать функцию, которая получает Task[], id и новый TaskStatus и возвращает массив с изменённым статусом только нужной задачи. Объяснить, у каких значений изменились ссылки и зачем остальные задачи возвращаются прежними. Затем коротко объяснить порядок проверки trash и допустимых статусов в onDragEnd.

Codex сначала проверяет попытку, затем даёт минимальную подсказку. Если возникают трудности с map, ограничить повторение этим фрагментом; уровень 3 пока не подтверждён.

## План

Работать по базовому распорядку из [системы обучения](learning-system.md), с перерывами и фиксацией активного времени. Одна главная задача — поиск фильмов; TS связан с её данными.

1. Повторение Kanban — 15 минут: функциональный setter, map/filter, ранние return.
2. Теория TS с маленькими самостоятельными попытками — 45 минут: литеральный union, unknown и narrowing, optional и null. Аннотация типа не проверяет ответ API.
3. Поиск фильмов: прочитать сохранённые критерии в предыдущем дне, проверить доступ к API и описать ожидаемый ответ. Без доступа записать блокер и проверить только интерфейс на примере данных.
4. По одному шагу: поле и кнопка → запрос → карточки с постером → loading/error/empty/success → повторный поиск и отсутствие постера.
5. Review, относящиеся к изменению проверки, журнал и Git-сдача.

Критерий результата: поиск по кнопке показывает реальные фильмы и постеры, пустой запрос и ошибка обработаны, повторный запрос работает. Ученик объясняет отличие введённого текста от отправленного запроса и самостоятельно сужает unknown в небольшом примере.

## Факт

- Дата, начало, активные минуты и перерывы: заполнить при занятии.
- Самостоятельная попытка и помощь: ещё не проведены.
- Доступ к API, реализация и проверки: ещё не выполнены.
- Большой пет-проект и требования ментора остаются в очереди; упражнение не подменяет его.
